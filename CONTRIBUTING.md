# Contributing

This initial repository snapshot prepares ELEC5620 Stage Two. Implementation begins through the team's Jira planning process.

1. Read the [Stage One baseline](docs/design-baseline.md) and the original report's relevant use case and diagrams.
2. Define a bounded Jira story with acceptance criteria, requirement references and validation evidence. Agree estimates and sprint commitments with the team.
3. Create a branch containing the actual Jira key, and make focused changes linked to that story.
4. Open a pull request describing the resulting behaviour, model traceability and validation. Use the supplied template.
5. Review and integrate the work, then update Jira with evidence and any follow-up tasks.

Record design deviations explicitly. Preserve deterministic calculations, validation, access controls, audited updates and version-specific owner approvals. Keep credentials and local environment files out of commits. Use simulated business data as required by Stage One.

Record each member's actual contributions as work occurs. The report's module leads provide context; Stage Two ownership and percentages must reflect the work performed.
