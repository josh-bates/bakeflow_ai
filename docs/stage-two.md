Source: [Stage Two marking criteria](reference/stage-2-marking-criteria.pdf). The supplied rubric states **1 November 2026, 11:59 PM** for source-code submission and a **Week 13 demonstration**. ## Evidence and submission checklist

- [ ] Map implemented stories and validation evidence to Stage One requirements and use cases.
- [ ] Demonstrate AI perception, proposals/decisions and interaction while preserving deterministic validation and owner approval.
- [ ] Keep genuine Jira activity throughout development, including reviews and feedback loops.
- [ ] Record technology choices and their practical value.
- [ ] Document setup, configuration, simulated data and execution steps once implemented.
- [ ] Rehearse deployment from the exact Canvas submission archive, including its external LLM access requirements.
- [ ] Complete the supplied contribution statement with names, student IDs, specific work and percentages by criterion. Each criterion row must total 100%; leave unused member columns blank.

These are future requirements, not completed checks. The rubric says equal contributions are assumed if no contribution statement is attached. Stage One contribution percentages must not be copied as evidence of Stage Two work.

## Planning issue to resolve

Lab Note 2 and the project requirement example both say that every member must implement at least two core features and one optional feature. The Stage One report assigns two main use cases to each member, but does not establish a per-member optional-feature implementation plan. Its text explicitly excludes live payment processing and automatic social-media publishing from the prototype.

During Jira refinement, map each member's core and optional contributions to the Stage One feature diagram and clarify any scope conflict with the tutor. Do not silently expand the prototype or mark an optional feature complete. The requirement example is a healthcare illustration, not a specification for BakeFlow AI.
